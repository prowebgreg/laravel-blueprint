# Implementation Plan: Media Engine & Asset Model

**Branch**: `003-media-engine` | **Date**: 2025-12-10 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/003-media-engine/spec.md`

## Summary

Phase 3 implements a complete media asset management system for The Blueprint CMS. The system handles image uploads with automatic WebP conversion and responsive variant generation, SVG sanitization for XSS protection, and video storage without processing. Media assets are linked to content models via the existing content_relations table using a HasMedia trait. The implementation uses Spatie Image for manipulation, Laravel queues for async processing, and S3/CloudFront for storage and delivery.

## Technical Context

**Language/Version**: PHP 8.3.x with `strict_types=1` in all files
**Primary Dependencies**: Laravel 12.x, Filament V3, spatie/image ^3.0, spatie/laravel-image-optimizer ^1.7, enshrined/svg-sanitize ^0.16
**Storage**: PostgreSQL 17 with JSONB, AWS S3 with CloudFront CDN, Redis for caching
**Testing**: Pest PHP with Laravel plugin, 70% minimum coverage (100% on critical paths)
**Target Platform**: Laravel Sail Docker environment (Linux)
**Project Type**: Web application (Laravel monolith)
**Performance Goals**: 20MB image processing in < 180s, 8 WebP variants per image
**Constraints**: Max file size 20MB, image dimensions 50-16000px, queue timeout 180s
**Scale/Scope**: Single media library, polymorphic relationships to 5+ content models

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| Large file processing timeout | 180s timeout, chunked processing, fail gracefully |
| S3 upload failures | 3 retries with exponential backoff, rollback on final failure |
| Orphaned S3 files | Weekly SyncOrphanedFilesJob reports mismatches |
| Broken images on frontend | Fallback image system returns placeholder |
| XSS via SVG uploads | enshrined/svg-sanitize removes all dangerous content |
